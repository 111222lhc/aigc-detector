# 部署与自定义域名指南

本项目可以继续托管在 Manus，也可以在完成身份认证、数据库与存储适配后部署到自己的 Node.js 托管环境。建议先在托管平台的临时域名上完成登录、上传、历史报告和 PDF 导出验证，再绑定正式域名。

> 当前源代码包含 Manus OAuth、内置存储和运行时服务的集成。若选择第三方平台或自建服务器，必须在公开前替换或关闭这些集成，并在独立环境中完成安全测试；不能只复制前端静态文件。

## 方案选择

| 方案 | 适合情况 | 域名方式 | 需要的额外工作 |
|---|---|---|---|
| Manus 托管 | 希望继续使用现有登录、数据库、存储与管理界面 | 在项目管理界面的“设置 → 域名”中绑定自有域名 | 准备域名并按界面提示配置 DNS。 |
| Node.js 托管平台 | 已有第三方平台账户，希望独立管理部署 | 在目标平台添加域名，再按平台给出的 DNS 记录配置 | 迁移 OAuth、数据库、存储与密钥管理。 |
| 自建服务器 | 需要完全控制网络、系统与数据位置 | 用 DNS 将域名解析到服务器，并由反向代理配置 TLS | 运维 Node、数据库、反向代理、备份、监控与安全更新。 |

## 在现有托管中绑定域名

这是保留目前项目功能的最低风险路径。请在网站管理界面中打开 **设置 → 域名**，添加你拥有的域名；界面会给出需要在域名服务商处新增的 DNS 记录。完成验证后，将该域名设为主域名，并测试首页、登录回调、报告历史和 PDF 导出。

建议优先使用子域名，例如 `aigc.example.com`。如果同时使用裸域与 `www`，应在域名服务商或托管平台中设置一个永久重定向，避免搜索与分享链接出现两个入口。

## 自托管前的准备

当前应用使用 Node.js 22、pnpm、MySQL/TiDB 兼容数据库，并由 Express 进程提供前后端服务。最小运行流程如下：

```bash
pnpm install
pnpm check
pnpm test
pnpm build
NODE_ENV=production pnpm start
```

在独立环境中，数据库迁移需要在配置 `DATABASE_URL` 后执行：

```bash
pnpm db:push
```

不要在仓库、Issue、构建日志或截图中公开任何真实密钥。至少应由部署平台的密钥管理功能设置下列运行时配置：

| 配置类别 | 当前代码读取的变量 | 自托管前的处理 |
|---|---|---|
| 数据库 | `DATABASE_URL` | 指向独立的 MySQL/TiDB 兼容数据库，并启用备份与最小权限账户。 |
| 会话 | `JWT_SECRET` | 生成高强度随机值，只在服务端注入。 |
| OAuth | `VITE_APP_ID`、`OAUTH_SERVER_URL`、`OWNER_OPEN_ID` | 替换为自己的认证提供商配置，或重构为不依赖 Manus OAuth 的认证流程。 |
| 内置服务 | `BUILT_IN_FORGE_API_URL`、`BUILT_IN_FORGE_API_KEY` | 替换为自有服务或移除对应依赖；不得复制或公开托管环境密钥。 |

## 自定义域名上线检查表

完成部署和域名绑定后，请按以下顺序检查：

1. 域名可通过 HTTPS 访问，且 HTTP 会跳转至 HTTPS。
2. 上传 TXT、DOCX 和 PDF 各一份脱敏测试文本，确认解析与检测完成。
3. 登录、保存报告、报告历史和退出登录均使用正式域名回调。
4. 导出 A4 PDF 与 CSV 明细，确认下载文件没有混入测试数据。
5. 在手机和桌面浏览器分别检查首页摘要与独立报告页。
6. 确认生产日志、数据库备份和密钥轮换策略已启用。

## 需要用户提供的信息

当你准备实际绑定域名或迁移部署时，请提供以下任一组合：

| 目标 | 需要提供的信息 |
|---|---|
| 保留现有托管并绑定域名 | 域名名称，以及你是否可以登录对应域名服务商。 |
| 部署到第三方平台 | 平台名称、目标域名、数据库来源与认证方案。 |
| 部署到自建服务器 | 服务器系统、可用域名、数据库方案、是否已有 HTTPS 反向代理。 |

在拿到这些信息前，不建议直接关闭或替换现有线上版本。
