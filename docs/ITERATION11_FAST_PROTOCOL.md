# Iteration11：速度优先的双向准确性验收协议

**状态：冻结候选与评估前的协议。**本轮目标不是仅提高某一份混合测试集的“总准确率”，而是在不让人类文本误报恶化的前提下，降低未见 AI 文本的漏检。任何阈值、特征权重或集成权重只能利用训练集与单独的校准集确定；全局留出、既有 OOD、短文本回归和用户反例不能参与选择。

## 为什么采用这套协议

RAID 说明，抽样策略、未见生成器、领域差异和轻度改写都能显著改变检测器表现，单一随机测试集不足以判断鲁棒性。[1] 另一项针对多种检测器的实证研究强调，应报告固定人类误报率下的 AI 命中率（TPR@FPR），而不是只报告平衡准确率；该研究在部分设定下观测到 TPR@1% FPR 降至 0%。[2] 对抗扰动研究进一步指出，小的字符或词语变化即可改变判别结果，因此本轮将最短文本和轻度扰动视为单独分层，而不混入总分掩盖失败。[3]

跨域共享任务表明，当训练与测试的模型和领域均被明确控制且可见时，可在固定 5% 人类误报率下获得很高的机器文本检出率；这不能外推为开放世界性能，但说明应同时记录“已见/未见”条件和固定 FPR 指标。[4]

## 数据分区与禁止项

| 分区 | 可用于什么 | 绝不可用于什么 |
|---|---|---|
| 训练池 | 拟合特征、分类器与样本权重 | 汇报最终性能 |
| 校准池 | 选择阈值、长度分层阈值或单一集成权重 | 训练模型参数、作为最终比较依据 |
| 冻结全局留出 | 最终一次性评估新的新闻人类文本与新增生成器文本 | 阈值/候选反复选择 |
| 既有 OOD、短文本回归、用户反例、GPT-5.5 留出 | 保护既有弱项、审计回归 | 训练或调参 |

所有划分采用**来源文档或提示家族级**隔离，而非窗口级随机划分；同一文档的相邻窗口、同一提示的改写版本不得跨训练、校准和留出。

## 快速候选路线

本轮只测试可在现有纯 Node.js 引擎部署的低风险方法：其一，在独立校准池选择**单一全局阈值**；其二，比较现有字符 n-gram 得分与长度、标点密度等确定性统计特征的线性后校准；其三，若样本充足，使用训练池内交叉验证产生的 out-of-fold 分数学习一个带 L2 正则的轻量堆叠器。长度或文体分层不得在全局留出上设定阈值。

不纳入本轮的快捷做法包括：用用户反例追加训练、在留出集上微调阈值、把大模型在线判断直接混入结论、或以任何单一总准确率覆盖分层退化。

## 双向上线门槛

| 指标 | 与 Iter5 比较的条件 | 通过要求 |
|---|---|---|
| 人类误报率（总体） | 冻结 OOD 人类与新增全局留出合并 | 不高于 Iter5，且 95% bootstrap CI 的上界不恶化超过 0.5 个百分点 |
| AI 漏检率（总体） | 冻结 OOD AI、GPT-5.5 留出与新增全局留出合并 | 低于 Iter5，且改进不只来自一个生成器或单一题材 |
| 固定 FPR 下的 TPR | 在独立校准池把 FPR 锁定为 1% 和 5%，再评估 | 至少一个固定 FPR 点的 TPR 改进，另一个不得退化超过 1 个百分点 |
| 最差分层 | 人类来源、AI 生成器、题材、长度短/中/长 | 不新增任何超过 Iter5 的严重退化（绝对差超过 2 个百分点） |
| 既有保护集 | 500 条短人类、33 条短抒情 AI、用户反例 | 短人类误报不升高；短抒情和用户反例命中不下降 |

总分（AUROC、平衡准确率或 F1）只做辅助描述，不能单独触发替换。样本量有限时，应同时报告点估计和自助法置信区间，并明确“未见生成器”“未见领域”的覆盖范围。
