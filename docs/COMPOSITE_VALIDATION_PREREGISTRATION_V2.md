# V2 综合模型能力验证预注册协议

**作者：Manus AI**  
**日期：2026-08-14**  
**状态：已预注册；尚未收集、生成或读取 V2 盲测文本**

## 1. 目的与决策对象

本协议用于评估是否应以微调后的 `AIGC_detector_zhv2` 候选替换当前线上 `iter5-char-2to4gram`。它回应的决策问题是：**候选能否在新的、完全未读取的跨文体与跨生成器测试中，显著提高综合识别能力，同时将人类文本误报控制在预先声明的可接受绝对范围内。**

本协议不重新解释已读的 V1 盲测。V1 的直接比较仍然有效且仅作描述性证据，详见 [`COMPOSITE_LOCKED_BLIND_COMPARISON_V1.md`](./COMPOSITE_LOCKED_BLIND_COMPARISON_V1.md)。V2 的数据、阈值、脚本版本、样本数量和通过条件一经冻结不得再修改；任何修改均必须建立新的版本号和新的盲测集。

## 2. 模型与阈值冻结

| 对象 | 冻结内容 | 允许的操作 | 禁止的操作 |
|---|---|---|---|
| 线上基线 | `iter5-char-2to4gram` 权重及评分逻辑 | 仅离线评分 | 修改特征、权重、阈值或预处理 |
| 候选 | 已完成的 `aigc_detector_zhv2_finetune_v1` 权重与 tokenizer | 仅离线评分 | 追加训练、重采样、选择性微调 |
| 阈值 | 每个模型均只能在**独立校准集**上锁定一次 | 在读取 V2 盲测前执行校准脚本 | 基于 V2 结果调阈值 |

V2 若需要与新综合门槛匹配的阈值，应建立独立于 V1、V2 盲测的校准分区；每类最少 60 篇，且所有文档 SHA-256 均不得与训练集、V1 校准集、V1 盲测集或 V2 盲测集重合。校准产物须在盲测评分前写入只读决策 JSON，并记录阈值、文件哈希和脚本哈希。

## 3. 新盲测设计

V2 盲测目标为 **320 篇文档**，其中 160 篇人类文本、160 篇 AI 文本。所有文档只会在冻结、评分与脚本校验均完成后才首次读取标签进行聚合；模型开发和阈值校准期间不得读取或使用其正文。

| 层 | 数量 | 预注册来源/生成方式 | 隔离要求 |
|---|---:|---|---|
| 人类：历史新闻 | 80 | 现有历史新闻来源中未进入任何旧分区的新文档 | 文档 SHA-256 与所有已用分区为零交集 |
| 人类：现代非虚构/散文 | 80 | 来源、版权与时间边界经单独审计的公开人类文本 | 不得来自 HC3、C-ReD、旧训练池或用户论文 |
| AI：本地 Qwen | 80 | 使用与人类层主题/长度匹配、但与 V1 不同的提示家族 | 与所有训练、校准和 V1 盲测文本 SHA-256 零交集 |
| AI：第二生成器 | 80 | 使用许可清晰、可在用户授权本地 GPU 上独立运行的第二个中文指令模型；模型名、许可证、版本、提示哈希须在生成前写入清单 | 不得使用候选检测器或其训练数据；与其余分区 SHA-256 零交集 |

第二生成器并未在本协议中预先指定为具体权重，避免在未核验许可证、显存可用性和来源前假定其可用。选择后必须先形成 `V2_GENERATOR_B_SELECTION.md`，记录权重哈希、许可证链接、设备预检与理由；该文件完成后，生成器选择才视为冻结。

## 4. 预先声明的主要指标

对同一 V2 盲测的每个模型，计算以下指标：总体准确率、平衡准确率、AI 类 F1、人类类 F1、宏平均 F1、AI 漏检率和人类误报率。AI 是正类，人类是负类；同时报告完整混淆矩阵和四个预注册分层的指标。

为描述不确定性，使用固定随机种子和 10,000 次成对文档自助法复采样，计算“候选减 Iter5”的 95% 百分位置信区间。复采样必须按文档配对，即每次抽到的文档同时使用两个模型的预测。

## 5. 综合上线门槛

候选仅在以下条件**全部**满足时才通过 V2 综合能力门槛：

| 门槛 | 要求 | 原因 |
|---|---|---|
| 总体准确率 | 候选比 Iter5 至少高 5.00 个百分点 | 防止仅改善极小样本或单一类别 |
| 平衡准确率 | 候选比 Iter5 至少高 5.00 个百分点，且差异 95% CI 下限大于 0 | 等权保护 AI 与人类两类 |
| 宏平均 F1 | 候选比 Iter5 至少高 5.00 个百分点，且差异 95% CI 下限大于 0 | 兼顾精确率和召回率 |
| 人类误报率 | 候选绝对误报率不高于 2.50%，且相对 Iter5 的误报率差异 95% CI 上限不高于 +5.00 个百分点 | 承认 0% 基线下的采样波动，同时限制真实人类文本风险 |
| 分层稳健性 | 四个预注册层中任一层的候选平衡准确率不得低于 Iter5 超过 2.50 个百分点 | 避免总体优势掩盖某一文体或生成器的严重退化 |

此处的 **2.50%** 是 V2 事前声明的业务风险上限，而不是由 V1 的 1% 结果反推出来的阈值。该上限代表网站仍须将少数可能误报的人类文本标记为“建议人工复核”，而不得表述为确定性判定。

## 6. 防泄漏与可复现性控制

所有分区使用正文 SHA-256 进行去重；同时保存来源标识、生成器/提示哈希、文件哈希和清单哈希。先以原子方式写入盲测文本及无标签清单，再冻结 SHA-256；评分脚本只读冻结文件；聚合脚本在运行前核验文件哈希、模型哈希、阈值决策哈希与“盲测未被训练脚本读取”的日志证据。

任何生成或评分任务中断时，只能从原子检查点继续；不得以部分结果筛选、删改或替换盲测文档。失败、拒绝样本与重试原因必须写入审计清单。

## 7. 部署顺序

通过 V2 综合能力门槛不是立即替换线上模型的充分条件。通过后仍须依序完成 ONNX 导出或蒸馏、与 Python 候选逐文档的推理一致性比较、Node.js 性能与内存测试、Iter5 快照回滚演练，以及网站质量门禁。任何一项失败均保留线上 Iter5，并将原因公开记录。

## 8. 当前状态

本协议已先于 V2 数据收集与评分写入。当前线上模型保持 `iter5-char-2to4gram`；候选模型仅作为待验证的离线比较对象。
