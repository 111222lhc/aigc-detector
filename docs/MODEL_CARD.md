# 文析 AIGC 检测模型卡与商用准备度说明

## 结论先行

当前系统**可以作为“人工复核优先级排序”的内部试用或受控Beta产品**，不应被宣传为已达到知网、PaperPass或任何特定商业检测服务的等同性能，更不应作为自动化学术处分、作者身份确认或单一合规判定工具。模型有可复现的离线隔离测试、可运行的产品闭环和错误提示，但尚未完成真实论文场景的大规模盲测、统计置信区间、独立第三方复现、压力安全测试与正式数据治理评估。

## 一、模型如何构建

系统不是关键词黑名单或规则匹配器。初始语料包含15,093条人类中文文本和99,874条AI文本；训练时，原始人类和AI语料均严格按隔行方式保留一半。随后额外加入与OOD测试目录隔离、且来源限定在2021年及以前的新闻、政府正式文书人类文本，以及多模型、多题材生成的AI文本。新增题材覆盖法律、书信、健康、旅行、纪实、产品介绍等，以降低“只会识别某一模型或某一种提示模板”的风险。

最终网页实际部署的是**字符2–4gram哈希线性分类器**。每一个600字符左右的文本窗口被拆成连续的2、3、4字符片段，映射到131,072维固定哈希空间，再做L2归一化并由逻辑损失线性分类器输出生成文本特征概率。它学习的是片段分布和组合模式，而不是对“因此”“首先”等单词计数。训练脚本还训练了45维文体统计分支（例如句子与标点、重复和连接性特征）用于离线比较；当前网页为了保持Node端推理可移植、可审计，使用的是经过导出验证的字符模型分支。

| 环节 | 实现 | 目的 |
|---|---|---|
| 原始语料减半 | 人类与AI主语料均使用`[::2]`子集 | 防止迭代直接记住全部旧训练样本 |
| 人类语料扩展 | 2021年及以前新闻、政府正式文书 | 扩展正式写作与旧文本分布 |
| AI语料扩展 | 多模型、多题材，法律与旅行题材额外加权 | 覆盖初轮发现的领域薄弱点 |
| 特征学习 | 字符2–4gram、131,072维哈希、L2归一化、逻辑线性分类 | 从语料学习可迁移模式而不是维护词表 |
| 输出聚合 | 段落/句子边界下约600字符窗口；按窗口字符数加权平均 | 避免单个局部片段决定全文结论 |

## 二、如何检验它是否“有效”

### 1. 先承认失败的基线

第一版在内部同源验证上看似很高，但在从未训练过的OOD数据上，AI漏检率高达97.9%。这说明它依赖了训练语料的格式与来源信号，**因此没有把第一版作为产品模型**。这一失败测试是后续迭代的起点，而非被忽略的负面结果。

### 2. 固定隔离OOD集不参与训练

`data/ood_test/`不被任何训练脚本读取。最终Iter5评估在854个人类窗口和442个AI窗口上进行，包含人类小说、旧报刊、散文、百科，以及AI日记、美食、健康、法律、书信、小说、产品、散文、演讲和旅行等域。这个集合不是完美的真实世界代表样本，但它比“训练集随机切分”更能揭示跨域问题。

| 指标（阈值50%） | 最终Iter5结果 | 含义 |
|---|---:|---|
| 人类窗口误报率 | 3.16% | 约3.16%的测试人类窗口被判为AI特征较强 |
| AI窗口漏检率 | 16.06% | 约16.06%的测试AI窗口未越过50%判定阈值 |
| 人类红色误报率（≥70%） | 1.41% | 高风险红色对人类窗口仍有误标可能 |
| AI红色命中率（≥70%） | 70.14% | 约七成测试AI窗口进入红色档 |
| 人类绿色比例（<30%） | 93.91% | 多数测试人类窗口落入低风险档 |
| AI绿色比例（<30%） | 6.11% | 仍有一部分测试AI窗口显示为低风险 |

这些指标来自`reports/ood_hybrid_iter5.json`。最重要的不是总平均数，而是逐域误差：旧报刊的人类误报率为5.76%，旅行类AI的漏检率高达46.74%。因此报告呈现窗口风险与人工复核提示，而不是“AI/人类”的确定性标签。

### 3. 迭代是否只是针对上一次文本优化

训练策略不是在OOD文本上调参，而是先从OOD评估中观察“哪一种**未见文体**差”，再从独立来源或新生成主题中引入同类但不同文本的训练样本，并重新对**同一份完全不参与训练的OOD集**评估。例如，法律AI漏检较高后加入新的法律正式文书生成样本；旅行域较弱后加入新的旅行攻略、游记、纪实类生成样本。每轮仍使用减半原始主语料。最终旅行域从较早迭代的73.9%漏检下降到46.7%，但仍远高于可忽略水平，因此被保留为公开限制。

这一流程比只看训练集或随机验证集更严格，但仍不是充分的“通用性证明”。原因包括：测试集规模有限；领域分布由当前构建者选择；没有对抗性重写实验；没有跨机构、跨年份、跨学科的真实论文盲测；尚未为误报、漏检计算置信区间。

## 三、网页如何从模型结果生成报告

服务端会先做换行和空白标准化，优先在段落和句末切分；过长连续文本再按600字符切开。每个窗口通过导出的模型权重得到0–100分。全文分数是各窗口分数按字符数的加权平均，随后映射为绿色（0–29）、橙色（30–69）和红色（70–100）。报告同时显示原文窗口、风险分布、风险趋势和橙/红色重点片段。

> 这个0–100分是模型对“该窗口接近训练语料中生成文本特征”的输出，不是事实概率，更不是对作者、写作过程或学术诚信的裁决。

## 四、我依据什么判断“可商用”

“可商用”不是单一准确率指标，至少需要模型有效性、产品可靠性、数据治理和场景责任四条证据链。当前完成情况如下。

| 商用门槛 | 当前状态 | 判断 |
|---|---|---|
| 可复现模型与隔离泛化测试 | 已完成；保留训练脚本、固定随机种子、逐域OOD结果 | 可支持受控试用 |
| 可用产品闭环 | 已完成；支持TXT/DOCX/PDF正文提取、临时检测、登录后保存、历史、打印报告和异常提示 | 可支持受控试用 |
| 基础自动化质量 | 已完成；11项前后端测试覆盖评分、风险档、输入边界和报告接口隔离 | 可支持受控试用 |
| 真实论文盲测与验收目标 | 未完成 | 不足以宣称成熟商用检测服务 |
| 对抗重写、翻译、混合写作与最新模型覆盖 | 未完成 | 误差风险未量化 |
| 置信区间、校准、阈值分场景配置 | 未完成 | 分数解释不够稳健 |
| 压力、并发、安全、渗透与灾备测试 | 未完成 | 不足以上公共生产流量 |
| 数据保留、删除、审计、告知与合同审查 | 未完成 | 需在处理真实论文前完成 |

所以，严谨的结论是：**当前版本具有“可部署的产品原型 + 有效性证据”的基础，可以用于封闭试点、人工辅助和持续收集反馈；但还不具备可以无保留对外承诺准确性、等同头部商业服务或用于高风险自动判定的证据。**

## 五、成为正式商用服务前的验收计划

1. 建立独立、盲标、不可回流训练的真实论文测试集，并按学科、年份、长度、作者群体、写作语言和来源报告指标；每个主场景应预先定义可接受的误报与漏检目标。
2. 对每个指标给出置信区间，单独评估AI原生、人工改写、翻译、混合写作、引用密集和扫描/OCR文本；据此做阈值校准，而不是把30%/70%当作普适法律或事实阈值。
3. 进行安全、负载、异常恢复、监控、数据留存/删除、访问审计和隐私告知测试，并让产品文案、客户合同和报告导出内容都明确“风险评估、需人工复核”的定位。
4. 先开展有人工复核和申诉流程的小规模Beta，锁定模型版本，持续记录真实误差；达到预注册验收目标后才逐步扩大使用范围。
