# 本地 ONNX 推理服务 V1

**状态：已在用户电脑上完成本机接口验证；尚未与线上网页连接。** 该服务的作用是让候选 BERT ONNX 模型在用户电脑上以受控 HTTP 接口运行，并为后续的 V2 Node.js 评分与独立服务器部署建立固定的请求、响应和安全契约。

服务只加载已经通过 Python 与 Node.js 固定夹具一致性验证的 FP32 ONNX 模型。它不包含训练文本、校准文本或盲测文本；不修改网站当前的 Iter5 引擎；也不会自行建立公网隧道、开放防火墙或绑定非回环网卡。

| 项目 | 已验证状态 |
| --- | --- |
| 监听地址 | `127.0.0.1:18765`，仅本机回环访问 |
| 运行进程优先级 | `BelowNormal` |
| 推理实现 | Node.js `onnxruntime-node`，CPU、单线程、低内存会话 |
| 模型常驻内存 | 约 467.32 MB RSS（用户电脑本机测得） |
| 健康检查 | `GET /health`，需要本地密钥 |
| 检测接口 | `POST /v1/detect`，JSON `{ "text": "..." }`，需要本地密钥 |
| 成功响应 | AI 概率、人类概率、预测标签、截断标志、延迟；不回传输入原文 |
| 鉴权拒绝 | 缺失或错误的 `x-aigc-api-key` 返回 HTTP `401` |
| 输入拒绝 | 非法或过短文本返回 HTTP `400`；正文和请求体均有长度上限 |

本机启动器在第一次启动时创建一个 32 字节随机密钥，并把它保存到用户电脑隔离目录内隐藏的 `local_service.env`。该文件不在 Git 仓库中、不上传到服务端，也不会显示在日志或接口响应中。该服务的当前请求队列为单请求，繁忙时返回 HTTP `429`，避免模型同时执行多个请求而争抢用户电脑资源。

## 本机验收记录

启动后的契约测试已经获得 `status: ok`：健康检查返回 `200`，单条中文检测请求返回 `200`，无密钥请求返回 `401`，过短正文返回 `400`。测试请求的端到端推理延迟为 **74.92 ms**。服务进程仅以 `BelowNormal` 优先级运行。

> 如果用户要玩游戏或需要立即释放资源，可运行 `stop-local-onnx-inference-service.ps1`。它只读取本服务自己的 PID 文件并结束该 Node.js 进程，不会停止其他程序或删除模型、导出文件与本地密钥。

## 线上部署前提

本地服务的成功并不等于已上线。现有网页运行环境只有 512 MB 内存，而本模型本机低内存会话已占约 467 MB。因此，在 V2 盲测通过前，网页继续使用 Iter5；V2 通过后也必须先选择有充足内存的独立服务器，配置服务器侧密钥、健康检查、超时、回退和访问控制，再将网页请求切换过去。
