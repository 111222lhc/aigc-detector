## 核验范围

此次核验确认了实际报告组件在桌面端与移动端的视觉结构，而非静态设计稿。报告标题使用“文本特征评估”“人工复核”等非裁决性措辞，未使用或暗示官方知网服务身份。

PDF 导出通过浏览器的打印功能完成；点击“导出 PDF”后在打印窗口选择“另存为 PDF”。“下载明细”单独生成带 UTF-8 BOM 的 CSV 文件，供表格工具打开并进行窗口级复核。

## A4 打印稿独立校验结论

使用本地无头浏览器直接将 `/?visual-audit-report=1` 导出为 A4 PDF 后，最终打印稿总计 **4 页**，且首页表单、导航中的导出按钮与非报告区块均不会进入归档版本。封面、编号、摘要指标、窗口明细和重点复核窗口均已保留，分页也没有切断单条明细。

首轮打印中，第二页“窗口风险分布”区域曾出现**图表标题存在但柱状图本体缺失**的问题。后续已为打印样式加入不依赖图表库的静态三色分布条，并在同步初始化视觉样稿后再次导出验证，确认 PDF 中已稳定保留低风险、中风险、高风险三条分布信息。

静态打印版分布条加入后，第二次无头打印一度出现**页面状态尚未完成便开始输出**、PDF 仅含首页表单的现象。该问题已通过将开发环境视觉样稿改为首屏同步初始化解决；再次导出后，报告内容恢复完整，说明打印链路不会因该样稿的异步状态而提前落盘。

## 真实检测结果页全链路核验

为避免只验证视觉样稿，本次额外增加了 `/?live-audit-report=1` 开发入口：页面加载后会通过网页实际 `detection.analyze` 路由调用当前 Iter5 引擎，生成一份真实检测结果，再用于桌面端、移动端和 A4 打印核验。

### 桌面端核验

桌面端全页截图显示，真实检测结果能够完整呈现以下结构：报告封面、报告编号、保存/下载明细/导出 PDF 三个操作入口、55% 总体风险分、2 个检测窗口、窗口分布、窗口检测明细以及重点复核窗口。首页表单仍保留在报告上方，说明即时检测场景下用户可以在同一页中完成提交与查看；报告本身的层级、留白和配色均正常。

### 移动端核验

移动端全页截图确认，报告卡片、分数环、关键指标卡、分布图和逐段明细均能在窄屏连续阅读。长文本明细仍然偏长，但没有发生文字溢出、按钮遮挡或分数标签错位。说明当前版式在手机宽度下已可用，不过若后续追求更强的移动端阅读舒适度，可以继续压缩明细文本字号或增强折叠阅读。

其中，真实结果页的分布信息显示为 **低风险 0 / 中风险 2 / 高风险 0**，并在打印稿第二页以静态条形图正确出现；第五页继续保留“重点复核窗口”区块，证明打印版不会只输出封面或丢失后续证据页。

### PDF 文本抽取复核

为使结论不只依赖截图，本次还对 `/home/ubuntu/live-report-print-audit.pdf` 执行了 `pdftotext -layout` 独立抽取。抽取结果中可定位到“检测报告”“窗口风险分布”“窗口检测明细”“重点复核窗口”四个报告关键标题，分别位于文本行 8、40、70、147；“真实检测结果全链路核验文档”位于第 18 行，且风险分布与两条中风险窗口分数均可被检索。

同一抽取结果中未出现“上传或粘贴论文正文”“检测正文内容”“开始检测”三个首页表单标签。这一正反向核对证明真实结果打印稿包含完整报告证据，而不包含首页上传与提交界面。
