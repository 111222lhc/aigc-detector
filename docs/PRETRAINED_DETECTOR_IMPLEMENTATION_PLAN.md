# 中文预训练 AIGC 检测器：强化微调与部署路线

**作者：Manus AI**  
**状态：已完成一轮本地 GPU 微调与锁定盲测；候选未通过人类误报保护门槛，线上 Iter5 未替换**  
**更新日期：2026-08-14**

## 结论

可以采用“下载已训练的中文检测模型，再用本项目严格隔离的新语料强化微调”的路线。当前最合适的起点是 `yuchuantian/AIGC_detector_zhv2`：它是公开、非门控的中文 `BertForSequenceClassification` 文本分类权重，标注 Apache-2.0 许可证，公开存储量约 818 MB，并且有对应的官方训练代码。[1] [2] 这比从零开始训练模型更现实，也比需要 `trust_remote_code=True` 的生成式检测器更便于安全审计。

本方案已在用户授权的 RTX 4060 Laptop GPU 上完成一轮保守微调、仅校准集阈值锁定和一次性隔离盲测。候选显著降低 AI 漏检，但将人类误报从 0% 提升至 1%，没有通过本项目冻结的双向部署门槛。因此，网站仍保留 Iter5。完整数据分区、训练配置、校准与盲测结果见[本地 GPU 微调与锁定盲测记录](./LOCAL_GPU_FINETUNE_V1_RESULTS.md)。

> 这条路线不是“下载权重后立刻替换网站”。预训练权重只能作为初始化；是否上线只能由本项目未见、文档级隔离的中文盲测集决定。

| 结论项 | 建议 | 原因 |
|---|---|---|
| 训练起点 | 优先评估 `AIGC_detector_zhv2` | 明确的 Apache-2.0 许可、中文 BERT 分类器、非门控权重和官方实现。[1] [2] |
| 训练方式 | 先做分类头/分层微调，再与现有 Iter5 做后验融合或蒸馏 | 让预训练语义表示补充字符风格特征，而不是盲目替换。 |
| 训练数据 | 仅使用与 HC3、C-ReD、公开权重训练来源尽量分离的中文论文级人类文本，以及由多种新生成器按同题提示产生的 AI 文本 | 防止数据重叠造成虚假的“提升”。 |
| 最终部署 | 优先蒸馏为当前 Node.js 可推理的轻量学生模型；必要时才采用独立 Python 推理服务 | 当前网站实时推理环境不适合直接承载 PyTorch BERT。 |
| 上线门槛 | 固定人类误报约束下，AI 漏检下降；同时总体和最差分层的人类误报不高于 Iter5，且有成对置信区间支持 | 避免用单一总准确率掩盖真实人类误判风险。 |

## 已核验候选与选择理由

`AIGC_detector_zhv2` 的公开 API 记录它兼容 `AutoModelForSequenceClassification`，采用 `BertForSequenceClassification` 架构，并包含标准 tokenizer、`config.json` 和 `pytorch_model.bin`，因此可用常规 Transformers 训练管线加载。[2] 它是优先候选，但其关联项目使用 HC3；现有项目也使用过 HC3。因此，本项目不能用与 HC3 重叠的样本来宣布它更强。

另一个可合法评估的候选是多语种 XLM-RoBERTa 检测器。它采用 MIT 许可、约 0.3B 参数、明确包含中文标签；但公开模型卡说明其中文训练数据来自 HC3-Chinese，且整体训练规模只有 900 个问答对。[3] 它可作为对照基线，却不应优先作为生产初始权重。`LLM-Detector-Small-zh` 虽有公开模型页，但模型卡可见内容没有明确许可证，且需要加载远程自定义代码；在许可和代码审计完成之前，不进入训练或部署流程。[4]

## 可执行流程

### 1. 在带 GPU 的离线训练环境复现基线

首先在**用户自有 GPU 电脑**或已有的第三方 GPU 环境中下载 `AIGC_detector_zhv2`，锁定权重哈希和许可证文本，并以冻结的未见样本仅做推理复现。当前项目运行环境没有 GPU；WebDev 部署环境也不适合承载 PyTorch BERT 训练或实时推理。因此，模型训练不能在当前线上站点直接进行。

初始复现不调参。输出应包含：逐文档预测、按“人类/AI × 文体 × 长度 × 生成器”的分层混淆矩阵、以及与 Iter5 的逐样本分歧表。只有确认基础权重在该盲测上具备可用信号，才进入微调。

### 2. 进行受控强化微调

微调集须按**文档和题目**分组，避免同一原文或同一提示出现在训练、校准与测试的不同分区。建议保留三部分：训练集用于参数更新，校准集用于选择阈值/融合权重，最终盲测集不参与任何模型选择。

训练从保守的分类头训练或较小学习率的逐层解冻开始，并记录随机种子、最大序列长度、批量大小、学习率、轮数和停止条件。候选不得因一次总分更高而自动胜出；每个候选都必须通过预先冻结的双向门槛。

| 验收维度 | 必须满足的条件 |
|---|---|
| 人类保护 | 总体人类误报不高于 Iter5；短文本、新闻/说明和论文级人类组不出现明显退化。 |
| AI 识别 | 在固定的人类误报约束下，AI 漏检低于 Iter5；新生成器与改写文本的最差组不能退化。 |
| 统计支持 | 使用同一冻结样本的成对自助法，对关键差异给出置信区间；不以小样本偶然波动替换线上模型。 |
| 可部署性 | 模型行为可复现，模型许可证明确，推理延迟与服务依赖符合网站运行边界。 |

### 3. 决定网站部署形式

**优先方案：教师—学生蒸馏。** 预训练 BERT 在 GPU 环境中作为教师模型，产出训练池的软标签、分歧样本和文档级分数；随后训练可在现有 Node.js 推理引擎中执行的轻量学生模型。这样网站不需引入 Python、GPU 或外部模型服务，并能保留当前低延迟结构。

**备选方案：独立推理服务。** 若 BERT 在严格盲测中有显著、无法蒸馏保留的收益，可部署独立的 Python/ONNX 推理服务，由网站后端经受控接口调用。它会增加运维、费用、延迟、模型更新和数据传输责任，不适合在证据不足时先行引入。

## 资源与风险边界

当前环境可以完成数据清洗、脚本编写、轻量模型训练、评估和网站整合；但 BERT 全量微调需要外部 GPU。一个持久服务器方案并不能自动解决该问题：无 GPU 的持久 VM 也不能高效完成训练。优先顺序应是用户自有 GPU，其次才是用户已有的第三方 GPU 账户；在取得用户许可前，不应开通付费算力或上传论文文本。

模型存在于公开平台不等于它在所有使用方式下都通过验证。尤其是检测器容易受生成器变化、人工改写、短文本和特定文体影响。公开权重只减少初始化成本，不能替代独立盲测、数据许可审计和产品级误差声明。

## 建议的下一步

当用户能够提供可用 GPU 环境时，实施顺序应为：先下载并哈希锁定 Apache-2.0 的 `AIGC_detector_zhv2`；再进行纯推理基准测试；之后以严格隔离语料进行一轮保守微调和蒸馏；最后与 Iter5 进行双向盲测。若没有候选同时改善 AI 漏检和人类误报，则继续保留 Iter5，而不以“模型更大”作为上线理由。
